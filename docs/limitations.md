# Difficulties and limitations

During development, OmniRoute was sometimes unavailable because its local process was not running, and Gemini returned a rate-limit error on one model. Some AI JSON responses also needed more robust type handling, while an early prompt caused the agent to stop with `needs_user` when it should have asked the manager for the restaurant name. We adjusted the status instructions, tested an alternative Gemini model, and added cautious Python confirmation checks. The agent was then demonstrated end-to-end between two Telegram accounts controlled by the developer: it initiated the request, received a manager-style confirmation, and sent a final reply. This **does not establish a real restaurant reservation** or a completed conversation with the assessment manager. The after-17:00 time safeguard was disabled locally to permit that evening's simulation, so the current configuration/code must not be reused unchanged for real bookings. The restaurant-name and confirmation rules are heuristic and cannot guarantee correctness for every unusual message. Voice messages were not implemented.
